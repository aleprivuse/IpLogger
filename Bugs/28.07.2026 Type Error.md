# Object Timestamp Becoming Undefined

## Problem

The timestamp was correctly parsed from `auth.log`, but it was not appearing in the UI.

The database stored the timestamp as `NULL`.

---

## Symptoms

The object was correct inside `insertIntoDatabase()`:

```javascript
{
    ip: "192.168.1.199",
    username: "maintest",
    attemps: 1,
    timestaps: "2026-07-27T09:32:22"
}
```

However, inside `insertDb()` the timestamp value became:

```text
undefined
```

The UI received no timestamp value.

---

# Debugging Process

## Step 1 - Check data flow

Checked the full data pipeline:

```text
auth.log
    ↓
Parser
    ↓
Object
    ↓
insertIntoDatabase()
    ↓
insertDb()
    ↓
Database
    ↓
UI
```

The parser and object creation were working correctly.

---

## Step 2 - Check object inside insertDb()

Added logging inside the database insert loop.

Found that the timestamp property was missing.

The database insert expected:

```javascript
attempt.timestaps
```

but the object contained:

```javascript
attempt.timestap
```

The property names were different.

---

# Real Cause

The class constructor had a spelling mismatch.

Expected property:

```javascript
timestaps
```

Actual constructor:

```javascript
this.timestap = timestap;
```

Because of the missing `s`, the object was created with:

```javascript
{
    timestap: "2026-07-27T09:32:22"
}
```

instead of:

```javascript
{
    timestaps: "2026-07-27T09:32:22"
}
```

JavaScript returned:

```text
undefined
```

because the requested property did not exist.

---

# Solution

Changed the class constructor property name to match the rest of the project.

Before:

```javascript
this.timestap = timestap;
```

After:

```javascript
this.timestaps = timestaps;
```

The timestamp correctly moved through the entire pipeline.

# Lessons Learned

## Object properties must match exactly

JavaScript does not understand similar names.

These are different properties:

```javascript
attempt.timestaps
```

and:

```javascript
attempt.timestap
```

A single missing character can break the entire data flow.

---

## Debug data flow step by step

When data becomes `undefined`:

1. Check where the data is created.
2. Check the object structure.
3. Check function arguments.
4. Find where the value disappears.

---

# Debugging Strategy

Do not immediately assume the database or UI is broken.

Trace the data:

```text
Where is the data created?
        ↓
Where is the data passed?
        ↓
Where does the value become undefined?
```
